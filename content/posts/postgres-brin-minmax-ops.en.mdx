`USING brin (col)` uses **minmax-ops** by default: for each range of `pages_per_range` pages, it records "the smallest and largest values seen in this range." It's not a histogram and not a Bloom filter—just a range summary.

## What's in a page range

For comparable types, each summary roughly contains:

| Field | Meaning |
|---|---|
| `min` / `max` | Lower/upper bound of the non-null values in the page range |
| Null-related flags | Whether the range is all null and whether it contains nulls (exact column names vary slightly across major versions) |

For a query like `WHERE ts BETWEEN $a AND $b`, the planner checks the summary: if the interval and `[min,max]` **don't overlap**, the whole range of pages can be skipped; if they overlap, the heap pages still have to be read and filtered. So BRIN wins by "reading fewer pages," not by "locating a row in one step."

```sql
-- Spell out the default opclass explicitly, for comparison with inclusion / bloom
CREATE INDEX ON events USING brin (created_at minmax_ops)
  WITH (pages_per_range = 32);

-- Check whether summaries are "loose": with poor correlation, max-min gets huge and the skip rate collapses
SELECT * FROM brin_page_items(get_raw_page('events_created_at_idx', 1), 'events_created_at_idx');
```

(`brin_page_items` / page numbers vary by version and index layout; in production, go by the heap blocks in `EXPLAIN (ANALYZE, BUFFERS)`.)

## Operational notes

1. **Correlation**: for fact tables appended in time order, minmax is tight; once out-of-order `UPDATE`s scatter the data, ranges widen and skipping stops working.  
2. **summarize**: after a large bulk load, run `SELECT brin_summarize_new_values('idx')` so pages don't sit unsummarized for long.  
3. **Don't expect accurate cardinality**: minmax has no NDV; if you picked the wrong column, don't blame the planner.

## In one sentence

**minmax-ops = a closed-interval label on each page range**; it's only cheap when correlation is good. For out-of-order writes, fix the write order or partition first, then think about tuning `pages_per_range`.
