媒体查询看的是 **视口**。同一张卡片塞进窄侧栏或宽主列时，按屏幕宽度切布局往往会错。容器查询让元素根据 **所属容器的尺寸** 改样子。

## 最小用法

父级声明容器：

```css
.card-list { container-type: inline-size; }
```

子级按容器宽度排版：

```css
@container (min-width: 360px) {
  .card { display: grid; grid-template-columns: 96px 1fr; }
}
```

`container-name` 可在多层嵌套里精确指定听谁的。组件库里把「列表项 / 卡片」做成容器感知，页面就少写特殊 class。

## 和媒体查询怎么分工

- **视口**：导航折叠、整页栅格、暗色偏好、触控粗细。
- **容器**：卡片内图文、工具条按钮疏密、模块在栅格不同列宽下的形态。

先容器、后视口，或反过来，团队约定一致即可；关键的是别两套断点各写各的数字。

## 注意点

旧浏览器要有降级（单列布局仍可用）。`container-type` 会影响子树的尺寸计算，避免在巨深的滚动容器上乱加。设计稿按「组件宽度档」标注，比只标 375/768/1280 更贴容器查询。

## 小结

响应式不止屏幕断点。让可复用块观察自己的槽位宽度，布局会稳很多，页面级 if/else 会少很多。
