浏览器原生 **CSS Nesting** 允许规则套规则。方便的同时，容易写出比扁平写法 **更高特异性** 的选择器。

## 等价形态

```css
.card {
  color: canvastext;
  & .title { font-weight: 600; }
  &:hover { outline: 1px solid; }
  @media (min-width: 60rem) {
    & { padding: 1.5rem; }
  }
}
```

大致等价于 `.card .title`、`.card:hover`、以及媒体查询里的 `.card`。`&` 代表父选择器；省略时部分引擎也会隐含父级，但显式 `&` 更稳。

## 特异性坑

1. **嵌套越深，复合选择器越长** → 特异性累加，盖不过去就要 `!important` 或改结构。  
2. `.card { &.is-on { } }` → `.card.is-on`（类×2），比单独 `.is-on` 更重。  
3. 与 `:is()` / `:where()` 混用时，`:where` 特异性为 0，可刻意降权；`:is` 取参数里最高的。

## 实践

- 组件根用单类，状态用修饰类（`.card.is-on`），嵌套不超过两层。  
- 工具类、重置仍扁平；嵌套留给「同组件局部关系」。  
- 审查时在 DevTools Computed 看获胜规则，而不是只看源码缩进。

## 一句话

**嵌套是语法糖，特异性仍按展开后的选择器算**；深套和 `&`+类叠乘是权重大户。
